## Reproduced test defect and fix

The feedback harness scheduled resizing every 30 seconds, so a documented
ten-second run could pass without any resizing. This is visible directly in the
saved `resize_actions: 0`; it is a coverage defect, not a reproduced renderer bug.

`tools/soak_uniforms.py` now uses `min(30 seconds, duration / 4)` for feedback
resizing, choosing a first size different from the initial window. It polls
window metrics until each requested logical size is confirmed, validates the
logical-size × scale to framebuffer-size relationship within one pixel, and
fails missing confirmations. JSON retains requested sizes, returned metrics and
latencies. `tools/run_acceptance.py` rejects feedback evidence without completed
resizes. The long-soak cadence stays at 30 seconds.

Regression tests exercise the actual timed loop with simulated OSC/clock data,
confirm three resizes in ten seconds, and reject ignored requests, stale metrics,
invalid Retina mappings and missing acceptance evidence. The corrected native
ten-second run now passes with three requested/confirmed resizes: 1280x720 logical
to 2560x1440 pixels, 960x540 to 1920x1080, then 1280x720 to 2560x1440. All report
scale 2; confirmation latency was approximately 20–22 ms. Evidence:
`build/platform-tests/macos-arm64-remaining-lpdK9W/feedback-resize/feedback.json`.
Metrics consistency alone does not qualify visible output, compositor behavior
or GPU allocation changes. Previous platform
feedback passes remain evidence of their recorded work, not retroactive resize
coverage. Shared harness changes need native regression on other targets as well.
